# Каталог на изложителите — Международен Панаир Пловдив

Двуезичен (BG/EN) онлайн каталог на изложителите с админ панел за въвеждане и
редакция на данните. Заменя стария каталог на `fairinfo.fair.bg`.

- **Публична част:** `/bg/...` и `/en/...` — търсене, филтри по изложение, бранш,
  държава, азбучен индекс, карти на фирмите, страница за всяка фирма и за всяко изложение.
- **Админ панел:** `/admin` — изложители, изложения, категории, импорт от Excel/CSV,
  потребители с роли.

За пускане в интернет вижте **[DEPLOYMENT.md](./DEPLOYMENT.md)**.

---

## Технологии и защо

| Слой | Избор | Защо |
|---|---|---|
| Framework | Next.js 16 (App Router), React 19, TypeScript | Публичният сайт и админ панелът са в един проект; страниците се генерират на сървъра (бързо и SEO-friendly); Server Actions вместо отделно API. |
| База данни | PostgreSQL + Prisma 7 | Надеждна и безплатна; `pg_trgm` индекси за бързо търсене по част от име (и на кирилица); Prisma дава четима схема и миграции. |
| Автентикация | Auth.js (NextAuth v5) | Вход с имейл/парола, bcrypt хеширане, JWT сесия в httpOnly бисквитка. |
| Двуезичие | next-intl | Адреси `/bg` и `/en`, hreflang, преводи в JSON файлове. |
| Стилове | Tailwind CSS 4 | Без тежка UI библиотека — малко JavaScript, бързо зареждане. |
| Изображения | sharp | Всяко качено лого се преоразмерява (≤600px) и конвертира в WebP. |
| Импорт | ExcelJS, PapaParse, Zod | .xlsx и .csv (UTF-8 и Windows-1251), валидация ред по ред. |

## Бърз старт (локално, за разработка)

Нужни: **Node.js 20.9+** и **PostgreSQL 14+**.

```bash
npm install                       # инсталира и генерира Prisma клиента
cp .env.example .env              # попълнете DATABASE_URL, AUTH_SECRET, ADMIN_*
npm run db:deploy                 # създава таблиците
SEED_DEMO=1 npm run db:seed       # администратор + демо данни (без SEED_DEMO: само администратор)
npm run dev                       # http://localhost:3000
```

Админ панел: http://localhost:3000/admin (данните за вход са от `ADMIN_EMAIL` / `ADMIN_PASSWORD`).

> Демо изложителите са измислени фирми — само за преглед на дизайна. В продукция
> пуснете `npm run db:seed` **без** `SEED_DEMO`.

## Модел на данните

```
Exhibition ──< Participation >── Exhibitor ──< ExhibitorCategory >── Category
 (изложение)   (щанд, палата,     (фирма)                          (бранш, по желание
               акцент, нов)                                          с подкатегории)
User (ADMIN | EDITOR) ──< AuditLog (кой какво е променил)
```

- **Щандът е към участието**, не към фирмата — една фирма има различен щанд на
  различните изложения. Там са и етикетите „Акцент“ (Featured) и „Нов изложител“.
- Двуезичните полета са `...Bg` / `...En`. Ако английското е празно, сайтът
  показва българското (`src/lib/i18n-fields.ts`).
- Държавата се пази като ISO код (`BG`, `DE`); името се показва на езика на
  посетителя чрез вградения `Intl` API.
- Статус на изложение: `DRAFT` (скрито), `ACTIVE` (в каталога и филтрите),
  `ARCHIVED` (само в архива и в историята на фирмата).

## Как работи

### Роли
| | ADMIN | EDITOR |
|---|:-:|:-:|
| Изложители: добавяне, редакция, публикуване | ✓ | ✓ |
| Изложители: изтриване | ✓ | — |
| Импорт от Excel/CSV | ✓ | ✓ |
| Изложения и категории: добавяне/редакция/изтриване | ✓ | само преглед |
| Потребители | ✓ | — |

Правата се проверяват **на сървъра** във всяка страница и всяко действие
(`requireUser()` / `requireAdmin()` в `src/lib/permissions.ts`) — не само чрез
скриване на бутони. Деактивиран потребител губи достъп веднага. Винаги остава
поне един активен администратор. След 10 грешни пароли входът за този имейл се
блокира за 15 минути.

### Импорт от Excel/CSV (`/admin/import`)
1. **Проверка:** файлът се чете и за всеки ред се показва „Нов“ / „Обновяване“ /
   „Пропуснат“ / „Грешка“ с обяснение. Нищо не се записва.
2. **Импорт:** записват се само валидните редове.

Колоните се разпознават по английски или български заглавия (`company_name`,
`Име на фирма`, `Щанд`…) — пълният списък е в `HEADER_ALIASES` в `src/lib/import.ts`
и на самата страница. Съществуваща фирма се разпознава по име; празните клетки
**не** изтриват въведени данни. С колона `logo_url` логата се изтеглят и
оптимизират автоматично — удобно за миграция от стария сайт.

### Лога
Качените изображения (до 8 MB, JPG/PNG/WebP/SVG…) се завъртат според EXIF,
смаляват до 600×600 px и конвертират в WebP (типично 10–30 пъти по-малки).
При липсващо лого се показват инициалите на фирмата в цветен квадрат.

### Търсене и филтри
Филтрите са в адреса (`?exhibition=agra-2027&category=agriculture&country=BG&q=...`),
така всеки изглед може да се сподели като линк. До всеки филтър има брой
резултати, изчислен спрямо останалите активни филтри. Търсенето намира част от
името (на кирилица и латиница) или точен номер на щанд. Акцентираните фирми са
най-отгоре.

### SEO
Всяка страница има собствено заглавие, описание, canonical адрес и hreflang
връзки bg↔en; фирмите имат schema.org `Organization`, изложенията — `ExhibitionEvent`.
`/sitemap.xml` и `/robots.txt` се генерират автоматично. Админ панелът и
филтрираните варианти на каталога не се индексират.

## Чести промени

- **Текст на сайта:** `messages/bg.json` и `messages/en.json` (ключовете трябва да съвпадат).
- **Цветове:** блокът `@theme` в `src/app/globals.css`.
- **Ново поле на изложител:** `prisma/schema.prisma` → `npm run db:migrate` →
  `exhibitorSchema` в `src/lib/validation.ts` → формата
  `src/app/admin/(panel)/exhibitors/exhibitor-form.tsx` и `actions.ts` →
  показване в `src/app/[locale]/exhibitors/[slug]/page.tsx`
  (и при нужда колона в `HEADER_ALIASES` за импорта).
- **Трети език:** добавете го в `src/i18n/routing.ts`, създайте `messages/xx.json`
  и полета `...Xx` в схемата.

> Next.js 16 има промени спрямо по-старите версии (напр. `proxy.ts` вместо
> `middleware.ts`, асинхронни `params`). Актуалната документация е в
> `node_modules/next/dist/docs/` — вижте и `AGENTS.md`.
