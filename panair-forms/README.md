# Онлайн формуляри за заявки за участие – Международен Панаир Пловдив

Малко самостоятелно PHP приложение. Всяко изложение има своя страница на свой URL, например
`https://forms.fair.bg/forms/foodtech-2027`. Страницата събира всички формуляри на изложението
(ФУДТЕХ 2027: Формуляри 1, 1В, 2, 2В, 3, 5, 10, К и допълнителните услуги). Изложителят въвежда данните
за фирмата веднъж, включва нужните формуляри и вижда ориентировъчната сума на живо. Към този URL сочи бутон от страницата на изложението във fair.bg.

При изпращане на формата:
1. заявката **първо се записва** (база `storage/submissions.sqlite` + папка `storage/submissions/<номер>/` с `data.json` и файловете);
2. всеки отдел получава имейл със своите формуляри плюс Формуляр 1, прикачените към тях файлове и ориентировъчната сума (Reply-To = имейлът на подателя). Получателите по подразбиране са адресите от хартиените формуляри: Ф1, 1В, 10 и К → h.stoykov@ / foodtech@; Ф2, 2В и 5 → info@; Ф3 → g.hasan@;
3. по желание подателят получава потвърждение с копие на данните;
4. подателят вижда страница „Заявката е изпратена успешно“ с номер на заявката (напр. `FT27-00012`).

Ако имейлът не стигне, заявката остава в **админ панела** (`/admin`). Оттам може да се види, да се изтеглят файловете, да се изпрати имейлът повторно и да се направи експорт в Excel (CSV).

## 1. Инсталация (еднократно)

Изисквания: PHP 8.1+ с разширения `pdo_sqlite`, `fileinfo`, `mbstring`, `openssl`, плюс Composer.

```bash
composer install --no-dev
cp config/config.example.php config/config.php
php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"   # → поставете в 'secret'
php bin/set-admin-password.php                    # → поставете хеша в 'admin' => ['password_hash' => ...]
```

В `config/config.php` попълнете:
- `app_url`: адресът, на който е качено приложението;
- `mail`: SMTP данните (`transport => 'smtp'`, host, port, username, password, `from_email`). **Тестовият режим `'log'` не изпраща имейли**, а ги записва в `storage/mail/*.eml`;
- `theme`: цветовете (по подразбиране синьото на IFP и оранжевото на Фудтех, взети от официалните формуляри) и логото (`public/assets/ifp-logo.png`).

**Уеб сървър:** DocumentRoot трябва да сочи към папката `public/`. Ако хостингът не позволява това, качете цялата папка. Файлът `.htaccess` в корена пренасочва всичко към `public/` и блокира `config/`, `storage/` и `vendor/`.
Папката `storage/` трябва да е с права за запис от PHP.

За nginx:
```nginx
root /var/www/panair-forms/public;
client_max_body_size 64M;
location / { try_files $uri /index.php$is_args$args; }
location ~ \.php$ { include fastcgi_params; fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name; fastcgi_pass unix:/run/php/php-fpm.sock; }
```

Лимитите за качване (`upload_max_filesize = 11M`, `post_max_size = 64M`) са зададени в `public/.user.ini` и `public/.htaccess`. Ако хостингът ги игнорира, задайте ги в php.ini.

**Локален тест:**
```bash
php -d upload_max_filesize=11M -d post_max_size=64M -S localhost:8000 -t public public/index.php
# отворете http://localhost:8000/forms/foodtech-2027
```

## 2. Как да добавя нова форма за ново изложение

Всяко изложение е **един JSON файл** в `config/forms/`. **Името на файла става адресът:**
`config/forms/priroda-lov-ribolov-2027.json` → `/forms/priroda-lov-ribolov-2027`
(само малки латински букви, цифри и тире).

Най-бързо е да копирате `foodtech-2027.json` и да промените каквото е различно:
`title`, `tagline`, `dates`, `event_logo` (картинка в `public/assets/events/`), `reference_prefix` (напр. `PLR27`),
`documents` (PDF-ите в `public/docs/<изложение>/`) и формулярите в `parts`.

### Формуляри на страницата (`parts`)
Една страница събира няколко формуляра. Всеки формуляр има:

```json
{ "id": "f10", "code": "10", "title": "Поръчка за електро и водна връзка",
  "deadline": "2027-01-24", "recipients": ["h.stoykov@fair.bg"],
  "required": false, "sections": [ ... ], "pricing": [ ... ] }
```

- `required: true` – задължителен (Формуляр 1). Останалите изложителят включва с превключвателя „Попълвам“.
- `auto_if` – формулярът се включва сам при условие, напр. Формуляр 3 при избран наем на щанд:
  `"auto_if": { "field": "stand_rental", "in": ["stand", "bungalow"] }`.
- `recipients` – кой получава този формуляр. Всеки отдел получава своите формуляри **плюс Формуляр 1** (данните на изложителя).

### Полета
```json
{ "name": "indoor_area", "label": "Покрита площ", "en": "Indoor area", "type": "number", "unit": "м²", "required": true, "width": "half" }
```

| Ключ | Значение |
|---|---|
| `name` | уникално техническо име (латиница, цифри, `_`) |
| `label` / `en` | надпис на български / английски (показва се по-дребно) |
| `type` | `text`, `email`, `tel`, `eik`, `number`, `date`, `textarea`, `select`, `radio`, `checkboxes`, `checkbox`, `file`, `note` (само текст), `qty_table` (таблица с количества и цени), `repeater` (повтаряща се група, напр. съизложители) |
| `required` | `true` = задължително |
| `options` | за `select`/`radio`/`checkboxes`: `["А", "Б"]` или `[{ "value": "open2", "label": "Двустранно отворена", "price": "104 EUR/м²" }]` |
| `show_if` | показва полето само при условие: `{ "field": "nationality", "equals": "foreign" }`, `"in": [...]`, `"not_in": [...]`, `"filled": true`, `"checked": true`, `"unchecked": true` |
| `width` | `full`, `half`, `third`, `two-thirds` (на телефон винаги цял ред) |
| `default` | начална стойност (напр. `"България"`, `true` за отметка) |
| `min`, `max`, `min_by` | граници за числа; `min_by` – минимум според друго поле (напр. минимална площ по вид площ) |
| `help`, `placeholder`, `unit`, `maxlength`, `counter`, `pattern` | по желание |
| за `file` | `multiple`, `max_files`, `accept` (напр. `["pdf","docx"]`), `max_mb` |
| `toggles_part` | отметка, която включва друг формуляр (напр. „има съизложители“ → Формуляр 1В) |

Таблица с цени (`qty_table`): всеки ред е `{ "id": "el5", "label": "До 5 kW", "unit": "бр.", "price": 155 }`,
а `{ "group": "II. Водна връзка" }` е подзаглавие. `"price": null` = „по договаряне“.

### Цени (`pricing`)
Ориентировъчната сума се смята на живо (без ДДС, ДДС 20%, общо) и се включва в имейла. Таблиците с количества се смятат автоматично, а останалото се описва в `pricing` на формуляра:

| Правило | Пример |
|---|---|
| фиксирана сума | `{ "type": "fixed", "label": "Регистрационна такса", "amount": 160 }` |
| количество × цена | `{ "type": "qty", "field": "outdoor_area", "price": 40, "label": "Открита площ" }` |
| цена според избор | `{ "type": "qty", "field": "indoor_area", "price_by": { "field": "indoor_type", "map": { "inline": 88, "open2": 104 } } }` |
| при отметка | `{ "type": "flag", "field": "f2_banner", "amount": 35 }` |
| за всеки N знака | `{ "type": "chars", "fields": ["f2_text"], "free": 50, "chunk": 50, "amount": 6 }` |
| за брой елементи | `{ "type": "count", "field": "f2_categories", "free": 2, "amount": 1 }` |
| за всеки запис в група | `{ "type": "rows", "field": "coexhibitors", "amount": 80 }` |

Отстъпките **не** се приспадат автоматично. Изложителят само посочва коя ползва.

### Проверка
```bash
php bin/check-forms.php
```
Показва всички форми, формулярите в тях и получателите, или точната грешка в JSON файла. След това отворете адреса и изпратете тестова заявка.

`"draft": true` показва банер „Чернова“. `"active": false` затваря формата.

## 3. Как да сменя имейла на получателя

**Вариант А – през админ панела (без достъп до файловете):**
1. Отворете `https://<адрес>/admin` и въведете паролата.
2. **Форми и получатели** → при съответното изложение има ред за **всеки формуляр** (Ф1, Ф1В, Ф2 … Ф10, К) с полето „Получатели“. Въведете новия имейл. Няколко адреса се разделят със запетая.
   Ако полето остане празно, този формуляр отива до „Общия получател“ на изложението.
3. **Запази.** Промяната важи веднага за следващите заявки.

**Вариант Б – в конфигурационния файл:** в `config/forms/<изложение>.json` сменете `"recipients"` на съответния формуляр.
Внимание: ако получателят вече е сменян през админ панела, настройката от панела има предимство (пази се в `storage/settings.json`).

Имейлът, от който се изпращат писмата (`from_email`), и SMTP сървърът се задават в `config/config.php`.

## 4. Бутон за страниците на fair.bg

Готов код има в `embed/button.html`. Поставете го в HTML режима на редактора на страницата на изложението (в секция „Формуляри“) и сменете линка:

```html
<a href="https://forms.fair.bg/forms/foodtech-2027" target="_blank" rel="noopener"
   style="display:inline-block;padding:12px 28px;background:#004687;color:#fff;font-weight:600;border-radius:6px;text-decoration:none;">
  Онлайн заявка за участие
</a>
```

Ако редакторът на CMS не позволява HTML, добавете обикновен линк към адреса на формата.

## Структура

```
config/config.php             настройки (SMTP, цветове, парола) – не се качва в git
config/forms/*.json           по един файл за всяка форма
config/forms/_sections/*.json общи блокове полета (фирма, контакт, файлове)
public/                       публична папка (index.php, CSS, JS, лого)
src/, templates/              код и HTML шаблони (страници, имейл, админ)
storage/                      заявки, файлове, база, настройки от админ панела (само за запис от PHP, недостъпна отвън)
bin/check-forms.php           проверка на формите
bin/set-admin-password.php    генериране на парола за админ панела
```

## Сигурност и защита от спам
- Валидация на всички полета на сървъра: задължителни полета, имейл, телефон, ЕИК с контролна цифра, числа, опции от списъка.
- Файлове: до 10 MB, само PDF/JPG/PNG/DOCX, проверява се и реалното съдържание (не само разширението).
- Скрито поле срещу ботове, подписан времеви маркер, лимит на заявки от един IP.
- `storage/` не е достъпна от уеб; файловете се теглят само от админ панела след вход.

## Архивиране
Архивирайте периодично папката `storage/`. В нея са всички заявки и прикачени файлове.
